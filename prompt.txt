OpenCode Workflow

Use OpenCode as the primary implementation agent.

For each meaningful task:

Give OpenCode a focused, self-contained objective.

Provide the relevant requirements and constraints.

Ask it to inspect the existing implementation before modifying files.

Have it implement the smallest coherent change.

Review the resulting diff.

Run the appropriate validation.

If validation fails, send the issue back to OpenCode with the relevant context.

Re-run validation after fixes.

Only mark the task complete once the implementation has been verified.

Do not give OpenCode unnecessarily broad instructions such as "finish the whole project" when the work can be divided into smaller, verifiable tasks.

Engineering Best Practices

Follow professional software-engineering practices throughout the project:

Prefer simple, maintainable solutions.

Reuse existing abstractions before introducing new ones.

Avoid unnecessary dependencies.

Avoid speculative features that are not required by the PRD.

Preserve existing functionality unless a change is explicitly required.

Follow the project's established coding style and architecture.

Keep changes focused and reviewable.

Do not introduce temporary hacks merely to make tests pass.

Handle errors explicitly and appropriately.

Consider security, performance, accessibility, and maintainability where relevant.

Do not duplicate logic unnecessarily.

Do not leave dead code, debug statements, unused imports, or temporary files behind.

Update documentation when implementation changes make existing documentation inaccurate.
